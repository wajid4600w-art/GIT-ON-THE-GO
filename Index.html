1 Open Source Control

Press Ctrl + Shift + G or click the Source Control icon on the left Activity Bar to view changed files.

2 Stage Changes (git add)

Hover over a file under Changes and click the + (Plus) icon to move it to Staged Changes.

3 Commit (git commit)

Type a message describing your update (e.g. "Add visual diagram") and click the ✓ Commit button.

4 Push to GitHub (git push)

Click Sync Changes or Publish Branch to send local commits up to your GitHub repository.

🚀 Core Workflow Execution Guide

1

1. Clone Repository (Remote ➔ Local)

Downloads a complete repository from GitHub to your local machine.

git clone https://github.com/username/repository.git
VS Code Direction: Press Ctrl + Shift + P ➔ Type Git: Clone ➔ Paste GitHub Repository URL.
↓
2

2. Check Status (Working Directory)

Inspects modified, added, or deleted files before staging.

git status
VS Code Direction: Look at the Source Control Sidebar. Badges show: M Modified, U Untracked, A Added.
↓
3

3. Stage Changes (Working Directory ➔ Staging Area)

Prepares specific changes to be bundled into the next commit snapshot.

git add .
VS Code Direction: Click the + icon next to individual files or next to the Changes section header.
↓
4

4. Commit (Staging Area ➔ Local Repository)

Saves staged snapshot permanently into your local Git history database.

git commit -m "Descriptive commit message"
VS Code Direction: Type message in the input box ➔ Click ✓ Commit button or press Ctrl + Enter.
↓
5

5. Push to GitHub (Local Repository ➔ Remote Cloud)

Uploads local commits to GitHub so team members or cloud backups can access them.

git push origin main
VS Code Direction: Click Sync Changes 🔄 in the bottom Status Bar or top of Source Control menu.

🛠️ Complete Everyday Git Commands Handbook

📁 1. Project Initialization & Remote Setup

Used when starting a new project from scratch or connecting local code to GitHub.

Initialize local repository:
git init
Creates a hidden .git folder in your current workspace directory.
Connect local repo to GitHub remote:
git remote add origin https://github.com/user/repo.git
Links your local folder to a remote repository URL named 'origin'.
Verify connected remotes:
git remote -v

🌿 2. Branching & Feature Workflow

Used to isolate experimental features or bug fixes from the main codebase.

Create and switch to a new branch:
git switch -c feature-login # or: git checkout -b feature-login
List all local branches:
git branch
The branch marked with an asterisk (*) is your current active branch.
Merge feature branch into main:
git switch main
git merge feature-login
Delete branch after merging:
git branch -d feature-login

🔄 3. Remote Syncing (Pull, Fetch & Push)

Used daily to keep local files in sync with teammates on GitHub.

Fetch changes without merging:
git fetch origin
Downloads remote updates to inspect before combining with local code.
Pull & merge remote updates:
git pull origin main
Shortcut for git fetch + git merge.
Push new branch & set upstream tracking:
git push -u origin feature-login
Sets default tracking remote branch so subsequent pushes require only git push.

🔍 4. History, Logs & Code Inspection

Used to track line-by-line differences and review past commit history.

View exact line changes before staging:
git diff
View clean single-line commit history:
git log --oneline --graph --all
Inspect details of a specific commit:
git show <commit-hash>

⚡ 5. Undoing Changes, Stashing & Safety Nets

Used when you make a mistake or need to quickly switch tasks without losing uncommitted work.

Temporarily shelf uncommitted changes:
git stash
Cleans working directory so you can switch branches cleanly.
Restore stashed changes:
git stash pop
Re-applies saved stashed edits back to your current working tree.
Discard uncommitted changes in a file:
git restore index.html
Unstage a file (keep local edits):
git restore --staged index.html
Soft undo last commit (keep staged files):
git reset --soft HEAD~1
Amend last commit message or files:
git commit --amend -m "Updated commit message"
